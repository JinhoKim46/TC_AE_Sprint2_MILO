The short version

What MILO is

A discovery chatbot for small business owners. An owner registers, describes how their business works, and MILO records each fact with the sentence it came from. On submit, the owner gets a report: their current process, what could be automated, which modules fit, and an indicative cost range computed in code from a rate card.

Where it stands

Built Every milestone from scaffold to evaluation is merged, verified by a separate agent, and security-tested. One sealed test run has been made.

Not live yet Production needs your items: consent text, an operator, database passwords, Supabase keys. The app refuses to start in production until they exist.

Level 2

How it was built

One integrator (Claude) ran a queue of agents. You set the goals and answered two questions; everything else was decided in the run and logged.

Roles

Builders, verifiers, security

Sonnet built most milestones in separate git worktrees. A fresh agent verified each one; it never graded its own work. Fable, later Opus, wrote protocols, audits and security reviews.

Rule

Protocol before result

Every experiment had a written protocol committed before its first number. Seven plus two more were written this way.

Rule

Dev for decisions, test once

All thresholds and model choices used the dev half of the data. The test half was opened once, at the end, and nothing was retuned after.

Rule

Pay only to measure

Writing, data, audits and reviews ran on the Claude subscription. OpenRouter was used only when a model itself was being measured.

Rule

Fail closed

Anything only you can do is a placeholder, and production refuses to start while a placeholder is in place.

Lane

Security red team

A threat model with 28 threats, 50 attack cases written before the defences, a review on every risky change, and a final pen test.

Level 2

Results on dev and on the sealed test split

Every number is as measured. Misses stay in the record; the test split was never used to tune anything.
